# 银之庭院 ·《魔法少女小圆》风格文字探险

同一个游戏，两个版本：**终端版**（Node.js 全屏字符界面）与**网页版**（Chrome / 手机浏览器）。
两边共用 `shared/` 里同一份数据、规则与功能清单，所以内容永远一致。

启动页是一块**正面居中的公告板**，右上角可以随时切换两块牌子：

| 主题 | 公告板标题 | 难度 |
| --- | --- | --- |
| 鹿目圆 | 《欢迎来到 银之庭院》 | 简单模式 · 希望尚存 |
| 晓美焰 | 《这里不是 银之庭院》 | 困难模式 · 时间不站在你这边 |

## 运行

### 终端版

```bash
npm start          # 或 node src/main.js
```

需要**交互式终端**。Windows 建议 Windows Terminal / PowerShell 7（老版 conhost 的 ANSI 支持不完整）。

### 网页版

```bash
npm run web        # 启动内置静态服务器，打开 http://localhost:5173/
```

也可以**直接双击 `web/index.html`** 用 Chrome 打开，不需要任何服务器和依赖。

手机（6.0 英寸及以上）已适配：

- `viewport-fit=cover` + `env(safe-area-inset-*)`，避开刘海与底部横条
- 高度用 `dvh`，地址栏收起/展开不会把按钮挤出屏幕
- 所有可点区域 ≥ 44px，`touch-action: manipulation`（不会误触缩放、没有 300ms 延迟）
- 字号用 `clamp()` 随屏宽缩放；横屏（矮屏）有单独的紧凑布局
- 日志区独立滚动，操作区固定在下方并限高，内容再多也不会顶掉状态栏

## 玩法

你在见泷原（中学、商店街、公园、神社、地下通道、废弃工厂）之间移动、探索、战斗。

- **灵魂宝石**会随着每一次行动变浑浊，到 100 就不再是你了。
- **悲叹之种**可以擦亮它，但数量有限。
- 见泷原有 **5 个魔女**，讨伐其中**任意 4 个**之后，回见泷原中学，天台那扇铁门会为你打开。

| 魔女 | 结界 | 血 / 攻 |
| --- | --- | --- |
| 蔷薇园的魔女 | 水名公园 | 95 / 9 |
| 箱之魔女 | 地下通道 | 125 / 10 |
| 零食的魔女 | 见泷原神社 | 155 / 12 |
| 影之魔女 | 废弃工厂 | 185 / 13 |
| **人鱼的魔女** | **夜晚的电影院**（商店街巷子深处，需「仔细调查」） | **195 / 14** |
| 魔女之夜 | 见泷原中学天台（终局，不可撤退） | 215 / 14 |

人鱼的魔女的结界里，那场管弦乐**不会停**：每回合额外污染灵魂宝石 +1，
即使你用「时间停止」冻住了她，音乐也照样在响。 correspondingly 她的奖励也是最丰厚的（悲叹之种 ×4）。
- 「集中」让本回合伤害减半，并把挡下的部分转化为一点恢复——打不到你的时候（比如焰的时间停止里）是回不了血的。

| | 鹿目圆（简单） | 晓美焰（困难） |
| --- | --- | --- |
| 生命 | 120 | 105 |
| 污浊速度 | ×0.55 | ×1.15 |
| 敌人攻击 | ×0.75 | ×1.25 |
| 撤退成功率 | 80% | 45% |
| 隐藏通路 | 直接可见 | 需要「仔细调查」 |
| 专属行动（冷却 3 回合） | **祈祷**：回血并擦亮宝石 | **时间停止**：冻结敌人两回合、下一击双倍 |
| 额外能力 | — | **时间回溯 ×3**：回到上一个安全的时刻 |

三种结局：`圆环之理` / `最后一次循环`（通关）、`银之庭院的居民` / `又一个我，留在了这里`（魔女化）、`在傍晚松开了手` / `在黑暗里松开手`（战败）。

## 目录结构

```
shared/              两个版本共用的核心（唯一的功能来源）
  themes.js          主题：配色、公告板文案、数值规则、结局
  content.js         见泷原地图、魔女、事件、愿望
  engine.js          规则引擎：探索 / 战斗 / 回溯 / 结局
  flow.js            菜单结构与输入处理（有哪些功能，由这里定义）

src/                 终端版：只负责画
  main.js            入口（终端初始化、输入解析、鼠标、状态机）
  ansi.js            ANSI 转义（真彩色 / 光标 / 鼠标）
  canvas.js          全屏字符画布（含中文全角宽度处理）
  screens/           board.js（公告板）· about.js（说明）· play.js（游戏）

web/                 网页版：只负责画
  index.html
  styles.css         手机适配在这里；配色由 themes.js 注入成 CSS 变量
  app.js

tools/
  serve.js           零依赖静态服务器（npm run web）
  check-sync.js      同步守卫（npm run check）
```

`shared/` 里的文件用的是 UMD 写法：Node 里 `require` 得到模块，浏览器里挂到 `window.Madoka`，
**同一个文件在两个环境里跑的是同一份代码**。

## 两个版本如何并行更新

规则很简单：

1. **功能（有什么、点了会怎样）只写在 `shared/`。**
   要加/删菜单项、事件、道具、结局、主题文案，改 `shared/flow.js`、`shared/content.js`、`shared/themes.js` —— 两个版本**同时拥有或同时失去**这个功能。
2. **`src/` 和 `web/` 只做渲染。**
   它们不允许自己定义菜单、文案或规则，只能把 `FLOW.playMenu(g)` 返回的东西画出来，并把按键/点击交回 `FLOW.playKey()` / `FLOW.playSelect()`。
3. **配色也只写一份。** `web/app.js` 会把 `themes.js` 的 palette 注入成 `--c-*` CSS 变量，不存在第二套色板。
4. 改完跑一次：

```bash
npm run check
```

它会验证：shared 在 Node 与浏览器两种环境都能加载、两个版本拿到的功能清单逐字相同、`web/index.html` 引用了全部共享模块、两个渲染层都没有私自夹带功能。

| 命令 | 作用 |
| --- | --- |
| `npm start` | 终端版 |
| `npm run web` | 网页版（内置服务器） |
| `npm run check` | 双版本同步检查 |
